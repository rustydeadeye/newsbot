# Instagram Carousel Pipeline: Figma + AI Content Engine

A practical pipeline for generating premium Instagram carousels at scale, using **Figma as the design source of truth** and a **code renderer for automated output**.

Target lanes: `ai_news` · `ai_explained` · `ai_for_business`

---

## Core Principle

Figma is the **template and design system layer**, not the runtime generation engine.

The pipeline has five stages:

1. Topic selected
2. Carousel blueprint generated by AI
3. Content mapped to a Figma-defined template
4. Slides rendered by code
5. Reviewed, published, and performance data fed back

---

## Start Here: MVP Workflow

Before building the full pipeline, validate with this setup:

1. Build 3 lane-based carousel systems in Figma (one per lane)
2. Create 3–5 slide templates per lane
3. Generate structured slide content with AI
4. Map content to template fields manually or semi-manually
5. Export from Figma with operator review
6. Post manually or via scheduler
7. Collect performance data — what hooks work, what layouts perform, what CTAs convert

This gives you creative control, brand quality, and real learning before committing to engineering.

---

## Stage 1: Topic Selection

Each carousel begins with a content topic and angle.

**Input schema:**

```json
{
  "lane": "ai_explained",
  "title": "Why Google's latest Gemini update matters more than it looks",
  "source_seed": "Google AI updates March 2026",
  "angle": "This is about distribution and workflow integration, not model quality."
}
```

**A good topic has:**
- One clear takeaway
- Enough substance for 5–7 slides
- A non-obvious angle (avoids surface-level reporting)
- Strong hook potential

## Stage 2: Carousel Blueprint

Before any visual work, the AI generates a full carousel blueprint.

**Output schema:**

```json
{
  "lane": "ai_explained",
  "carousel_type": "myth_vs_reality",
  "hook": "Most people are reading this AI update the wrong way",
  "slide_count": 6,
  "slides": [
    {
      "slide_number": 1,
      "role": "cover",
      "headline": "Most people are reading this AI update the wrong way",
      "support": "The real story is not the model. It is where Google is placing AI."
    },
    {
      "slide_number": 2,
      "role": "myth",
      "headline": "What most people think",
      "support": "Google just added another Gemini update."
    },
    {
      "slide_number": 3,
      "role": "reality",
      "headline": "What is actually happening",
      "support": "Google is embedding Gemini inside tools people already use every day."
    },
    {
      "slide_number": 4,
      "role": "deeper_meaning",
      "headline": "Why this actually matters",
      "support": "Distribution beats capability when the gap closes."
    },
    {
      "slide_number": 5,
      "role": "implication",
      "headline": "What it means for you",
      "support": "Your workflow tools are about to make decisions for you."
    },
    {
      "slide_number": 6,
      "role": "cta",
      "headline": "Save this. The next update will make more sense.",
      "support": null
    }
  ],
  "caption": {
    "hook": "Most AI updates sound bigger than they are.",
    "expansion": "The real question is whether it changes how people work, build, or buy. That is where the signal is.",
    "cta": "Save this for later."
  },
  "visual_direction": "clean editorial, muted background, strong headline hierarchy, subtle diagram shapes"
}
```

**Rules for this stage:**
- Decide what belongs on each slide before touching design
- No raw paragraphs — every slide has a role and a point
- Headline does the work; support adds context only
- Max 2 lines for headline, 2–3 lines for support

## Stage 3: Figma Design System

Figma holds the visual language for all carousels. Build it once, reuse it always.

### File Structure

**Page 1 — Foundations**
- Color tokens (backgrounds, text, accent, muted)
- Typography scale (headline, subhead, body, label, eyebrow, CTA)
- Spacing system
- Grid (1080×1350, 4:5 portrait)
- Icon set

**Page 2 — Components**
Reusable building blocks:
- Headline block
- Stat card
- Quote block
- Comparison module
- Icon cluster
- CTA row
- Divider / rule
- Label / eyebrow strip
- Accent shape / gradient block

**Page 3 — Carousel Templates**
Master templates organized by lane and slide role. Each template has named, clearly labeled editable fields.

**Page 4 — Exports** *(optional)*
Finalized instances ready for manual export.

### Template Families by Lane

**`ai_news`**
`cover` → `what_happened` → `what_changed` → `impact_card` → `who_it_affects` → `takeaway`

**`ai_explained`**
`cover` → `myth` → `reality` → `deeper_meaning` → `implication` → `cta`

**`ai_for_business`**
`cover` → `pain_point` → `common_mistake` → `better_way` → `workflow_card` → `outcome` → `soft_cta`

### Editable Field System

Every template exposes a fixed set of named fields that map directly from the content engine. Do not design templates with freeform text — always named, typed fields.

**Standard field types:**
`headline` · `subhead` · `body_short` · `body_medium` · `label` · `eyebrow` · `quote` · `stat` · `cta` · `accent_color` · `icon_name` · `image_placeholder` · `background_style`

**Example template definition:**

```json
{
  "template_id": "ai_explained_myth_01",
  "lane": "ai_explained",
  "slide_role": "myth",
  "editable_fields": ["headline", "subhead", "label", "accent_color", "icon_name"]
}
```

### Visual Hierarchy Rules

Every template must enforce hierarchy — slides should feel designed, not written.

| Level | Element | Rule |
|-------|---------|------|
| 1 | Main headline | Largest type, strongest contrast, 1–2 lines max |
| 2 | Support / subhead | Smaller, lower emphasis, adds context only |
| 3 | Meta | Label, eyebrow, CTA, source — smallest, decorative role |

**Design principles:**
- Large type on key slides
- Generous whitespace — less copy, more breathing room
- Visual anchors on every slide: shape, card, line, icon, or gradient
- No paragraph-heavy slides — if it takes three sentences to explain, restructure the content

## Stage 4: Template Mapping

Once the blueprint is generated, each slide is automatically mapped to a Figma template.

**Mapping logic** (rules-based, per lane):

| Lane | Slide Role | Template ID |
|------|-----------|-------------|
| `ai_explained` | cover | `ai_explained_cover_01` |
| `ai_explained` | myth | `ai_explained_myth_01` |
| `ai_explained` | reality | `ai_explained_reality_01` |
| `ai_explained` | deeper_meaning | `ai_explained_split_01` |
| `ai_explained` | implication | `ai_explained_implication_01` |
| `ai_explained` | cta | `ai_explained_cta_01` |

This mapping can be a simple lookup table or an LLM call if slide roles don't match cleanly (e.g. unusual carousel types).

**Mapped output:**

```json
{
  "carousel_id": "car_1021",
  "lane": "ai_explained",
  "slides": [
    {
      "slide_number": 1,
      "template_id": "ai_explained_cover_01",
      "fields": {
        "headline": "Most people are reading this AI update the wrong way",
        "subhead": "The real story is not the model. It is where Google is placing AI.",
        "label": "AI Explained",
        "accent_color": "#3B4FE4"
      }
    }
  ]
}
```

## Stage 5: Rendering

### Phase 1 — Manual / Semi-Manual (MVP)

Best for early-stage, high quality control, low volume.

1. Blueprint generated and mapped
2. Operator updates Figma instances from mapped fields
3. Slides exported manually at 1080×1350px
4. Review and post

**Limitation:** Does not scale past ~5–10 carousels per week without operator bottleneck.

> **Note on Figma's export API:** Figma's REST API supports programmatic export but has rate limits and per-export latency that make it impractical for high-volume automated pipelines. Use it for low-volume or on-demand exports only.

### Phase 2 — Code Renderer (Scale)

Figma defines the visual language. A code renderer reproduces it automatically.

**Recommended stack: Satori + resvg**

- Write slide templates as React components
- Satori converts them to SVG
- resvg converts SVG to PNG
- No browser dependency, fast, deterministic output

**Why this over alternatives:**

| Option | Tradeoff |
|--------|----------|
| Satori + resvg | Fast, headless, React-based — best fit |
| Playwright screenshot | Reliable but slow; needs browser overhead |
| HTML/CSS + canvas | Flexible but complex font/layout handling |
| Figma API export | Brittle at scale, rate-limited, slow |

Each Figma template maps to a React component. The component accepts the same field schema defined in Stage 4. When content is mapped, the renderer calls the right component with the right fields and outputs a PNG.

### Phase 2 Output

```
/exports/car_1021/
  slide_01.png
  slide_02.png
  slide_03.png
  slide_04.png
  slide_05.png
  slide_06.png
  caption.txt
  metadata.json
```

**Export settings:**
- Resolution: `1080 × 1350px`
- Format: PNG (lossless) or JPG at 95%
- Aspect ratio: `4:5` portrait
- Export each slide individually

## Stage 6: Caption

Caption is generated separately from slide copy and is as important as the visuals.

**Structure:**

1. **Hook** — one strong opening line (not a summary, a statement or question)
2. **Expansion** — 2–3 short lines of context or insight
3. **CTA** — one soft action prompt
4. **Hashtags** — 3–5 relevant tags, optional

**Example:**

```text
Most AI updates sound bigger than they are.

The real question is whether it changes how people work, build, or buy.
That is where the signal is.

Save this for later.

#artificialintelligence #aitools #techstrategy
```

**Rules:**
- First line must work standalone — it is what appears before "more"
- No recap of slide content
- CTA should feel natural, not promotional
- Avoid hashtag stuffing

---

## Stage 7: Review

Every carousel goes through review before publishing.

### Content QA

- [ ] Hook is strong and non-obvious
- [ ] Slide order flows logically
- [ ] No overcrowded slides
- [ ] No paragraph-length support text
- [ ] CTA is subtle and appropriate
- [ ] Caption hook works standalone

### Visual QA

- [ ] Hierarchy is clear on every slide
- [ ] No awkward line breaks in headlines
- [ ] Visuals support the message
- [ ] Consistent spacing across slides
- [ ] No text near image-safe margin edges

### Technical QA

- [ ] All slides exported at correct resolution
- [ ] Correct slide count (Instagram max: 10)
- [ ] File sizes within platform limits
- [ ] Font rendering correct

## Stage 8: Performance Feedback Loop

The pipeline does not end at publish. Performance data feeds back into content and template decisions.

**Track per carousel:**
- Reach
- Saves (strongest signal for carousel content)
- Shares
- Profile visits
- Comments

**Feed back into:**

| Signal | Action |
|--------|--------|
| High saves | Replicate hook style, topic type, slide count |
| High reach, low saves | Hook works, content depth needs improvement |
| Low reach | Hook underperforming — test different angles |
| High comments | Topic resonates — build follow-up carousels |
| Template performs consistently | Promote it to primary template for that lane |

Review performance weekly. Update template priority and content patterns based on what the data shows, not assumptions.

## Automation

The pipeline can be ~85–90% automated. The remaining 10–15% is human review of hook quality and visual output.

### What Can Be Fully Automated

| Stage | How |
|-------|-----|
| Topic selection | RSS feeds, news APIs, trend monitoring → LLM filters and scores by lane fit |
| Carousel blueprint | LLM call with structured output |
| Template mapping | Rules-based lookup table, or LLM for edge cases |
| Slide rendering | Satori + resvg pipeline, triggered per carousel |
| Caption generation | Separate LLM call with caption-specific prompt |
| Technical QA | Automated checks — character limits, slide count, file size, resolution |
| Publishing | Instagram Graph API — supports carousel posting programmatically |
| Performance collection | Meta Insights API — reach, saves, shares pulled automatically |

### What Cannot Be Fully Automated (Reliably)

**Hook and angle quality** — The LLM will generate a hook every time. Whether it is genuinely non-obvious or just sounds smart is hard to evaluate automatically. Mediocre hooks at volume will tank performance quietly.

**Visual spot-check** — Code can check character counts and margins. It cannot catch a headline that wraps awkwardly, a font rendering artifact, or a slide that just looks off. A 30-second human look catches these.

**Performance interpretation** — You can collect the data automatically. Deciding what it means requires judgment.

### Full Automation Stack

```
Cron / scheduler
      ↓
News ingestion (RSS + APIs)
      ↓
LLM topic scoring and selection
      ↓
LLM carousel blueprint generation
      ↓
Rules-based template mapping
      ↓
Satori + resvg renderer → PNGs
      ↓
Automated QA checks
      ↓
[Human review gate — 30–60 seconds]
      ↓
Upload images to CDN → pass URLs to Instagram Graph API
      ↓
Carousel posted
      ↓
Meta Insights API → performance logged
      ↓
Weekly LLM summary → fed back into topic scoring weights
```

### Instagram Graph API Notes

- Requires a Facebook Business account connected to an Instagram Creator or Business account
- Images must be publicly accessible URLs — upload PNGs to CDN or S3, pass URLs to the API
- Carousel posting requires a two-step call: create media containers per slide, then publish as carousel
- Rate limit: 25 API calls per hour per user token
- Stories and Reels cannot be posted via API — feed carousels only

### Recommended Approach

Run fully automated into a fast-pass review queue. A human spends 30 seconds approving or rejecting before the system posts. This protects quality without creating a bottleneck.

Once you have 2–3 months of performance data and validated what good output looks like, raise the automation threshold and only flag edge cases for review.

## Long-Term Architecture Summary

```
Topic Selection
      ↓
AI Carousel Blueprint (hook, slides, caption, visual direction)
      ↓
Template Mapping (rules-based or LLM-assisted)
      ↓
Renderer (Satori + resvg → PNG slides)
      ↓
QA Checks (automated + human review gate)
      ↓
Publish via Instagram Graph API
      ↓
Performance Data → back into topic selection and template priority
```

**Figma is used for:** designing templates, iterating on visual language, maintaining brand consistency, defining the field system.

**Figma is not used for:** runtime content generation, automated export at volume.
